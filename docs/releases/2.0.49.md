# 2.0.49

## 日志量：从"几十万行"到几乎为零
现场实测（206，2.0.48 之前）：`/data/nx5gui_live.log` 每 200 KB 里
`[selopt] stored …` 占 **63%**（2470 行），其余是 `[entity]`、`[mips]`、
`[mijia]` 逐包细节。这些全部改写为统一日志的 **DEBUG** 级：
默认**不进内存环、不落盘、不写 stdout**，只有开启临时诊断时才可见/可查。

具体收口：
- **实体引擎** `ic_log()`：原每行 `write(1)` 到 stdout → 改为统一日志；
  正常细节 DEBUG，`fail/error/deny/timeout/reject` 关键字自动升 WARN 落
  `network.log`。**不再写 stdout。**
- **选择项存储** `[selopt] stored …`：DEBUG（原占日志 63%）。
- **米家 MIPS**：逐包 `reply:` 与 `read-loop alive` 心跳（60 s 节流）→ DEBUG。
- **触摸注入** `[pump] TOUCH …`：改由 `NX5_UI_DBG` 门控（默认关）。
- 黑匣子镜像：米家轮询/实体缓存/发现提交/预分配等逐秒细节并入 DEBUG 分类。

实测效果（206，空闲稳态）：
- `/data/nx5gui_live.log` **15 秒增量 = 0 字节**（此前同样时长远超数十 KB）；
- 重启后 1 分钟总大小约 8.8 KB（仅启动横幅与少量状态行）；
- 统一环 `suppressed` 持续增长而 `dropped` 下降——细节被有意丢弃，
  关键事件（界面/控制/连接/错误）仍完整可见。

## 新增客户端接口
- `nx5_log_debug(module, fmt, ...)`：细节只进统一日志（DEBUG）。
- `nx5_log_allow(key, interval_ms)`：热路径节流（同 key 窗口内只放行一次）。

## 继承 2.0.48
- DEBUG 默认不进内存环 + `suppressed` 计数；2.0.47 的 P2 生产者迁移。
