# 2.0.44

## 崩溃修复：面板反复"崩溃"直至压黑（内核 OOM）
- 现网表现为面板突然黑屏/反复重启：实际不是 GUI 自身崩溃，而是**内核 OOM 杀掉 nx5gui**。
- 触发链：通话结束后厂商 `sipservice` 音频线程进入死循环，每帧刷一行
  `Audio_Play_Thread: PlaybackDevice_Write return 0` 到 `/tmp/sip.log`；
  tmpfs 页面计入内存，`/tmp`（44.8 MB）被灌满即把整机 RAM 吃光，
  GUI 每次启动都因内存不足被 OOM 击杀 → 启动-被杀死循环 →
  显示 Owner 连续失败 5 次后关背光。
- 修复：`sipservice` 的输出改为丢弃（该服务只有这类刷屏；语音诊断看
  `/data/baresip.log` 与 `nx5sip_helper` 日志），并在启动前把
  `/tmp/sip.log`、`/tmp/ic_flight.log` 超过 1 MB 的先截断。
- 现场设备（206）已就地生效：`/tmp` 占用 100% → 3%，GUI 进程稳定。

## 继承 2.0.43
- 分时段屏幕亮度（含移动端面板）、状态更新不再整片卡片区重绘、
  对讲弹窗悬垂指针崩溃修复、Wi-Fi 离线 10 秒快探、
  崩溃日志新增 `build` 标识与候选返回地址。

## 说明
- 若后续仍观察到 `sipservice` 长时间高 CPU（刷屏已不再吃内存，但仍占 CPU），
  需要厂商侧修音频线程；届时可加"死循环自动重启 sipservice"守护。
