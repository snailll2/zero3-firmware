# Zero3 2.0.13 · 性能与内存优化、移动端首页拆分、设置页崩溃修复

<!-- OTA_NOTES: 运行内存降至约 28MB(原 45MB),翻屏只重绘卡片区、启动空闲预渲染不阻塞触摸|Web 首页拆为 5 个分区并新增 CPU/内存/负载运行曲线|修复设置页点击切换导致 GUI 反复崩溃|卡片与屏幕数量超限在保存时明确报错 -->

- 运行内存显著下降：设备事件队列改为轻量状态引用（不再每事件内嵌完整实体状态），跟踪实体表按需扩容；每屏布局状态按 stride 紧凑打包。整机基线 RSS 由约 45.2MB 降至 27.6–29MB。
- Web 实体接口的 gzip 与分片缓存增加闲置回收（90s / 300s）并 `malloc_trim`，长时间运行内存不再虚高。
- 渲染与翻屏优化：相同文本不重复刷新、背景/导航/滑块等样式幂等写入；卡片刷新按内容签名跳过无变化重建；每屏画面缓存并带 6MB/9MB 内存水位逐出。
- 翻屏只重建卡片区域，顶部状态栏与导航仅在原位更新高亮；冷启动首访各屏仍有一次性构建。
- 启动后空闲切片预渲染：首帧完成且 3 秒无触摸时按 2 张卡/60ms 切片预建其余屏幕，内存不足自动让位，不影响触摸响应。
- **修复设置页「点击切换」导致 GUI 反复崩溃**：上一版性能优化为设置页加了对象名字索引，缓存裸对象指针，而设置屏内 Wi-Fi 列表、弹窗与主题切换会删除并重建对象，悬垂指针在校验时触发 SIGSEGV（`pc` 恒在 `lv_obj_is_in_widget_tree`）。已回退为树内安全查找，设置页四套主题反复切换与导航往返实测零崩溃。
- 容量与边界：每屏最多 24 张卡、最多 8 屏、布局 JSON ≤64KB；网页保存超限时返回明确错误（第 N 屏超过 24 张 / 屏幕数量超过 8 个），不再静默失败。
- 枚举值表由 32 加宽到 48，修复长选项（空调模式、风扇档位等）被截断的问题；相关能力数组同步加宽。
- Web 移动端首页拆分为「设备概览 / 运行性能 / 快捷操作 / 记录与维护 / 服务连接」五个分区：概览页高度约减半，分区条单行不折行，KPI 压缩为 4 列×2 行。
- 新增「运行性能」面板：CPU 占用、内存占用、系统负载三张 90 点曲线，2 秒轮询、页面隐藏时暂停，数据来自 `/api/stat`。
- 「记录与维护」分区将维护入口（网络与 Web / 黑匣子诊断 / Web 终端）置顶，实体操作与事件列表及分页排在其下。
- 排版页移除常驻的卡片计数条；24 张/屏上限校验与超限提示保留。

## 安装

- 在线：Web「配置备份与升级」检查更新、下载，再确认安装。
- 离线：上传 `zero3-2.0.13.signed.tar.gz`，由设备验证后安装。
- 完整部署：解压 `zero3-2.0.13-full-deploy.zip`，将整个目录传入设备，执行 `sh install.sh --check`、`sh install.sh`，然后重启。
- 一键入口：发布仓 README 中下载并执行 `installer.sh`，自动获取当前最新版。
- **1.x 老设备**：直接用完整部署包或一键入口升级到本版；升级会替换应用层，账户、授权、Wi-Fi、布局与卡片配置保留。

已有账户、授权、Wi-Fi、布局、场景和自定义卡片配置保留。此包是应用层完整部署，不是内核或分区镜像。
