# 2.0.34

## HA 状态"一直未获取"修复
- 根因：面板 **eth0 接收大响应在 ~13KB（12KB+MTU）后停摆**（已知驱动/硬件缺陷）。HA `/api/states` 约 1.1MB，发现请求永远拉不完 → 实体池只剩米家 884，HA 实体 0 → 所有卡片"未获取状态"；小请求正常，所以表现为"HA 初始化很慢"。
- 现象取证（`/data/ha_link_guard.log`）：`FAIL via eth0 (direct) 13246 B` → `reset eth0 (down/up)` → `OK via eth0 1123266 B`；随后引擎 `discover commit ha=1486 merged=2370 total=295ms`。

## 交付内容
- `ha_link_guard.sh` 纳入固件安装包（`/data/bin/ha_link_guard.sh`），不再依赖手工下发
- 开机启动：`start_app.sh` 在环境加载后延迟 45 秒拉起看护进程，每 5 分钟探测一次 HA 全量 states（≥300KB 视为正常）；异常时先复位 eth0（down/up），仍失败则把 HA 的 /32 路由切到 wlan0；全部失败回退系统默认路由，下个周期再试
- 看护日志：`/data/ha_link_guard.log`（OK/FAIL、复位、接口切换）

## 验证
- 本机实测 eth0 停摆后执行一次看护：探测 13246 B 失败 → 复位 eth0 → 1123266 B 成功，HA 池 1486 实体立即补齐，卡片状态全部恢复
- 升级到本版后看护进程随开机自动运行，不再需要人工执行
