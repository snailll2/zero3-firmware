# 2.0.50

## Web 设置：日志级别与临时调试
- 系统设置 → 维护 → **日志记录级别**：ERROR / WARN / INFO / DEBUG / TRACE。
  级别即"允许进入内存环的最大详细度"，默认 INFO。
- **临时调试日志**：一键开启 10 分钟（可延长），窗口内放开 DEBUG/TRACE 并写入
  `diagnostic.log`，到期自动关闭；界面显示剩余分钟。
- 设置写入 `/data/nx5_conf/intercom/logging.json`，`nx5_logd` 2 秒内热加载。
- 页面同时显示日志占用：统一日志目录 / 活动日志 / 内存环。

## Web 设置：一键清理日志（含历史目录）
- 「查看清单」先给出将清理的**全部文件清单**（路径、大小、类别），不删除任何东西。
- 「清理全部日志」执行后返回**释放清单**（每个文件的大小与成败、总释放字节、失败数）。
- 覆盖范围：
  - 活动日志（原地截断，保留 inode）：`nx5gui_live.log`、`/tmp/ic_flight.log`、
    `baresip.log`、`nx5sip_helper.log`、`nx5ic_helper.log`；
  - 统一日志目录：`/data/log/nx5/*`（runtime/control/network/upgrade/crash/diagnostic）；
  - 历史/遗留：`wifi_health.log`、`key_evt.log`、`ha_link_guard.log`、`btproxy.log`、
    `btproxy_scan.jsonl*`、`zbbridge.log`、`zb_reset.log`、`kmsg.log`、`bx2.log`、
    `nx5gui_crash.log`、`automation_audit.log`、`/data/log/*.log`、`*-install.log`；
  - 厂商/临时：`/tmp/sip.log`、`/tmp/mgw*.log`、`/tmp/log/*`（msg_mgw_bt 等）、`/tmp/logd.out`。
  - **默认不碰**配置、证书、账号、布局、升级包；呼叫/报警业务记录需显式勾选才清。
- 实测（206）：一次清理 24 个文件、释放 ≈2.4 MB（二次清理含活动日志再释放 1.48 MB），
  失败 0。

## API
- `GET/POST /api/logging`：读取/保存级别与临时调试（POST 需 `X-NX-Request: 1`）。
- `GET /api/logging/cleanup`：清理清单预览。
- `POST /api/logging/cleanup`：执行清理并返回释放清单。

## 继承 2.0.49

## 说明
- 清理不重置内存环（`/tmp/nx5/log/ring.bin`），历史事件仍可查；
  需要"从零开始"时重启 GUI 即可（环随 tmpfs 生命周期）。
- 清理是白名单机制，不接受任意路径，不存在把配置/业务文件误删的入口。
