# 2.0.51

## 修复：开机亮屏约 20 秒后黑屏（进程正常）
- 现象：冷启动后界面先正常显示，约 20 秒后整屏变黑，背光仍亮、网页/接口都正常。
- 原因：2.0.42 引入的原厂语音服务 `sipservice` 被安排在界面显示之后启动，它启动时会
  重置媒体系统并清掉界面的显示图层；重复启动或退出时还会把显示输出整个停掉。
- 修复：
  - `sipservice` 改为在显示初始化**之前**启动并等它完成，且每次开机只启动一次；
  - baresip / nx5sip_helper 同样每次开机只启动一次（看护循环重入不再产生双实例）；
  - 显示 Owner 新增显示链看护：检测到显示被其它程序停掉或清图层时，自动重建显示
    会话并重新拉起界面（实测外部重置后约 7 秒恢复，有限速不会循环）；
  - 热替换/重启显示 Owner 后不再留下黑屏。
- 新增手动入口：`POST /api/display/recover`（会重启界面）。

## 日志设置迁入黑匣子诊断页
- 「记录级别」「临时调试日志（10 分钟）」「日志占用」「查看清单 / 清理全部日志」
  从系统设置移到 **黑匣子与系统诊断** 页（与运行日志同屏），系统设置里只保留
  一个「打开」入口。
- 写操作改为显式 `X-NX-Request: 1`（此前用通用 write 简写被服务端拒绝，
  表现为"点了没反应"）。

## 运行日志按级别过滤
- 页头「运行日志」的级别下拉真正接上统一查询：
  `全部级别 / ERROR / WARN / INFO / DEBUG` → `/api/system/logs?level=…`，
  切换即刷新（此前该下拉是空壳）。

## 「清空日志」升级
- 改为调用 `/api/logging/cleanup`：截断活动日志、删除遗留/历史目录/厂商临时日志，
  并清空旧黑匣子缓冲；完成后提示释放字节与文件数。
- 业务记录（呼叫/报警）仍需在清理项里勾选才清。

## 继承 2.0.50
- 记录级别 / 临时调试 API、清理清单与释放清单、日志量削减。

## 说明
- 页面改动需强制刷新（Cmd/Ctrl+Shift+R 或关闭标签重开）后生效。
- 语音对讲依赖的原厂 `sipservice` 仍然保留（拾音前端由它初始化），只是启动时机
  调整到显示之前。
