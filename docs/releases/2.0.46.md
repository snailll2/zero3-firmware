# 2.0.46

## 统一日志服务（P1 基础设施）
- 新增独立进程 `nx5_logd`：**唯一日志写入者**，GUI/服务只通过非阻塞 Unix 数据报提交。
  - GUI/业务线程提交不阻塞、不写盘；队列拥塞只计数丢弃，不影响界面与控制。
  - 有界内存环 `/tmp/nx5/log/ring.bin`（512 条 × 384 B），web 只读 mmap 查询。
  - 只有 ERROR/WARN、崩溃记录与（用户临时开启时的）INFO 落盘，分类
    `/data/log/nx5/{runtime,control,network,upgrade,crash}.log`，单文件轮转，
    目录总预算 8 MiB。
- 统一查询 `GET /api/system/logs`：真实 `timestamp` / `level` / `module` / `event` / `op` /
  `elapsed_ms`，支持 `level=`、`module=`、`limit=1..512`、`cursor=<seq>` 增量拉取，
  并返回 `dropped`/`seq`/`capacity`。环不可用时自动回退旧黑匣子视图。
- 崩溃应急槽：GUI 启动时预开 `/tmp/nx5/log/crash.bin`（4×512 B 定长），
  信号处理器只做 `pwrite` 一条定长记录（含 sig/addr/pc/lr/sp/build），
  `nx5_logd` 每 2 秒摄取进统一环并落 `crash.log`；stdout 不可达也能留证。
- 外部程序采集：`nx5-logd --capture <module> -- cmd`（封装为 `nx5-log-run`），
  baresip / nx5sip_helper 输出改由采集器接管（不再各自写 `/data/*.log`）；
  低频脚本事件可用 `nx5-log <level> <module> <event> msg`。
- 兼容：`ic_flight_event` 仍写原黑匣子环与 `/api/flight`，同时镜像进统一环；
  旧页面/接口不受影响，后续版本再切到统一视图。

## 短期兜底（P0）
- `storage_guard.sh` 补齐审计发现的未入列写入者上限：`key_evt.log`、
  `ha_link_guard.log`、`automation_audit.log`、`baresip.log`、`nx5sip_helper.log`、
  `nx5ic_helper.log`、`btproxy_scan.jsonl` 等，避免遗留/回退路径无限增长。
- 厂商 `sipservice` 输出保持 `/dev/null`（2.0.44 起），防止刷屏灌满 tmpfs。

## 继承 2.0.45
- HA 断链指数退避重连、`ha_link_guard` 按内容判成败且只复位有线口。

## 说明
- 本版为 P1 基础设施 + P0 兜底，**业务日志生产者迁移（P2）与页面/升级收口（P3）
  仍按方案分阶段进行**：尚未迁移的 printf/fprintf 仍走原 stdout 与既有上限，
  不会因此新增无界写入。
- `/tmp` 只存运行期环与 socket（约 200 KiB），重启即清空；持久记录仅关键项。
