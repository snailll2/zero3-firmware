# 2.0.33

## OTA 空间回收
- 升级下载/安装前先检查 `/data` 可用空间；不足时自动清理**发布流程自己产生的历史备份**，再重新校验空间：
  1. `web/index*.bak*` 旧网页备份：仅保留最新一个
  2. `/data/nx5gui.bak*` 手动备份：全部删除（安装器在安装时会对当前程序做事务备份）
  3. `/data/deployment-backups/*`：先保留最新一个，仍不足再全部删除
  4. 顺带清理残留 `nx5gui.new` / `nx5gui.installing`
- 不触碰用户配置、用户文件、vendor 资源和运行中的 `nx5gui`
- 回收过程写入飞行日志：`OTA space reclaim start/done free_kb=… freed_kb=…`
- 应用到在线下载预检（size+4MB）和安装前预检（size+16MB）两处；释放后仍不足才报“空间不足”

## 背景
现场 `/data` 仅 160MB，多次部署/升级累计的历史备份（gui `.bak`、旧网页 `.bak`、deployment-backups）可达 40MB+，导致升级预检 26MB 直接失败。本版后升级不再需要人工清盘。

## 验证
- 2.0.32→2.0.33 真机在线升级：面板原本只剩 22MB 可用且保留一份 12MB `nx5gui.bak`，升级时自动回收后通过预检、下载、安装并成功重启到 2.0.33
负载大小：10243248 字节；MD5：`bb9524973f137a079abef1616e51cfe0`。
