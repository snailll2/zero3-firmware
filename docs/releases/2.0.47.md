# 2.0.47

## 日志治理 P2：生产者迁移
- **按键**：`nx5_key_evt_note` 原来每条事件 `fopen + fflush` 写
  `/data/key_evt.log`（热路径同步刷写 flash）。改为统一日志 `module=key`，
  只进内存环；`/api/system/logs?module=key` 可查，不再产生该文件写入。
- **Wi-Fi**：`wifi_log` 不再直写 `/data/wifi_health.log`；状态进 `module=wifi`
  （失败/异常自动升 WARN 落 `network.log`）。旧黑匣子文本仍镜像一份。
- **自动化审计**：不再直写 `/data/nx5_conf/automation_audit.log`；
  改 `module=ctl event=automation`，来源 IP 进 `op` 字段，
  拒绝/失败升 WARN 落 `control.log`，成功只进内存环。
- **蓝牙 / Zigbee**：`btproxy.sh`、`zbbridge.sh` 由 `nx5-log-run` 采集
  （module=`ble` / `zigbee`），不再各自重定向到 `/data/*.log`。
- **HA 链路看护**：`ha_link_guard.sh` 的 log 走 `bin/nx5-log`
  （module=`ha_guard`，FAIL/reset 用 WARN），logd 缺席时退回原文件。

## 行为说明
- 上述模块的旧日志文件不再新增；既有文件保留（`storage_guard` 仍兜底上限）。
- 崩溃记录、ERROR/WARN、升级失败等关键记录仍按分类落盘，可在
  「黑匣子」页用 `module=`/`level=` 过滤查看。
- 队列拥塞时只计数丢弃（`dropped` 可在 `/api/system/logs` 响应里看到），
  不阻塞 UI/控制线程。
